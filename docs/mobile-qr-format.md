# Mobile QR config format (ATCQR1)

`mobile_qr.py` encodes atc's config (with secrets resolved from the keychain)
into a QR code for the Android app to scan. Since v1.20.0-era security pass,
the payload is always passphrase-encrypted — this doc is the wire format spec
so the Android-side scanner can be implemented or re-implemented to match.

## Wire format

```
"ATCQR1:" + base64( salt[16 bytes] + nonce[12 bytes] + ciphertext_and_tag )
```

- Everything after the literal ASCII prefix `ATCQR1:` is base64-encoded bytes
  (standard base64, not URL-safe), so the whole QR payload stays printable
  ASCII for both the terminal-printed QR and any saved PNG.
- `salt` — 16 random bytes, freshly generated every time a QR is produced.
  Never reused, even for the same passphrase.
- `nonce` — 12 random bytes (AES-GCM standard nonce size), also freshly
  generated every time.
- `ciphertext_and_tag` — AES-256-GCM output: ciphertext with the 16-byte GCM
  authentication tag appended (this is what `AESGCM.encrypt()` returns in
  Python's `cryptography` library and most standard AES-GCM implementations —
  no separate tag field to parse out).

## Key derivation

```
key = scrypt(
    password = <passphrase, UTF-8 bytes>,
    salt     = <the 16-byte salt from the payload>,
    N        = 2**15   (32768)
    r        = 8
    p        = 1
    dklen    = 32       (AES-256 key)
)
```

This is the same scrypt parameter set and the same AES-256-GCM cipher atc's
own secrets backend already uses for `keyrings.cryptfile` (see `atc secrets
migrate-encryption`) — deliberately reusing one audited crypto configuration
instead of inventing a second one.

## Plaintext payload

Once decrypted, the plaintext is UTF-8 YAML — the same structure
`build_mobile_yaml()` in `mobile_qr.py` produces today (top-level keys:
`proxmox`, `pihole_instances`, `plex`, `tautulli`, `radarr`, `sonarr`,
`seerr`, `portainer`, `beszel` — see that function for the exact per-service
field names). The format of that inner YAML is unchanged by the ATCQR1
wrapper; only the QR payload itself changed from "raw YAML" to "ATCQR1
envelope around encrypted YAML."

## Reference implementation

`mobile_qr.py`'s `encrypt_payload()` / `decrypt_payload()` functions are the
canonical reference — same repo, same commit that introduced this format
(`fix(security): passphrase-encrypt mobile QR config payload`). Any other
implementation (e.g. Kotlin/Java on Android) should produce byte-for-byte
identical ciphertext given the same passphrase, salt, and nonce, which you
can verify with a cross-language test vector.

## Passphrase handling

- Minimum 8 characters (enforced CLI-side at generation time; the Android
  side should accept any string — the length floor is just a usability
  nudge, not something encoded in the wire format).
- Never written to disk, never passed as a CLI argument, never logged.
- Not stored anywhere — the user types it at generation time and again at
  scan time. A wrong passphrase decrypts to garbage and fails the GCM tag
  check (`InvalidTag` in Python; the Android equivalent is whatever your
  AEAD library raises on tag mismatch) rather than silently returning wrong
  data — AES-GCM is authenticated, so tampering/wrong-key is always detected.

## Backward compatibility

This format has no predecessor to stay compatible with — it replaces the
original plaintext-YAML-only QR payload outright. A scanner that expects raw
YAML will not understand an `ATCQR1:`-prefixed payload (and vice versa), so
the Android app's QR-scan feature needs this decrypt step implemented before
QR codes generated by `mobile_qr.py` v1.20.0+ will import successfully.
